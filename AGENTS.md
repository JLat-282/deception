# Deception project guidance

## Public-facing product language

- Do not expose internal milestone, planning, architecture, or validation
  language in the player-facing interface.
- Assume invited testers already understand the build stage unless the product
  explicitly requires onboarding copy that says otherwise.
- Public copy should explain game mechanics, player choices, consequences, and
  recovery actions—not what the team is currently testing or which development
  layer is active.
- Keep labels such as “baseline,” “playtest,” “prototype,” “Layer 1,” and
  implementation notes in repository documentation rather than product UI or
  browser titles unless the user explicitly requests them.
- Before handing off frontend work, perform a public-copy sweep and remove text
  that describes the development process instead of the player experience.
